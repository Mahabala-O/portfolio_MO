SQL Lab is a free tool for improving at SQL interview problems. A diagnostic of 14 LeetCode-style tasks pinpoints where your SQL breaks down. A practice set then trains those gaps one topic at a time, starting with easy problems and building to hard ones. It runs entirely in the browser, and anyone can copy it to build practice around their own gaps.

## Summary

- **Diagnose, then practice.** The diagnostic combines 14 query tasks with 11 concept checks and ends in a skill report. The practice set is organized by topic, and each topic opens with a lesson and moves from Easy to Hard.
- **Graded like an interview.** Column names must match the prompt, a requested sort order requires an `ORDER BY`, and missing rounding counts as wrong. Hidden tests target the edge cases that trip up medium-level answers: ties, NULLs, duplicate rows, and month and leap-year boundaries.
- **Built to be reused.** The project is an open-source template. Anyone can copy it, take the diagnostic, and add topics for their own gaps, using an AI assistant for the first draft and the built-in checks to verify it.
- **Every requirement is tested.** An automated check confirms that each requirement in every prompt is enforced by at least one test: 134 requirements across 22 problems.

## The problem

I could solve most of LeetCode's easy database problems, but medium problems took me far longer, especially those involving window functions. I couldn't say exactly which concepts were slowing me down, and "practice more SQL" isn't a plan. I wanted a tool that would tell me precisely what to work on.

My first diagnostic run answered that. It pointed to one pattern above all: ranking rows that are themselves aggregates, such as finding the top-selling product in each category with tie-breaks. That pattern is the core of problems like *Seasonal Sales Analysis*, so it became the first practice topic.

## How it works

Every problem includes sample data, a reference solution, and hidden tests. Each hidden test adds a few rows designed to expose one specific mistake. When a hidden test fails, it opens as its own tab, showing the rows it added and letting you run your query against that data until it passes.

![A failed hidden test opened as a tab. The query groups by product name, so two different products named Tee are counted as one.](/images/sql-lab/failed-test.png)

Each topic begins with a worked example. The lesson runs the query live and shows the output of every step, so you can see exactly what each stage of the query receives. The same step-by-step view is available in every problem.

![The lesson for "Aggregate, then rank," showing the worked example and the output of each step](/images/sql-lab/lesson.png)

Problems increase in difficulty one element at a time. The second problem provides the full query except for the ranking step; later problems add a join, a `CASE` bucket, a second tie-break, and a second window function. Solved problems stay in the list with your best time, so you can return and solve them again.

## Testing the tests

Taking the first version of the diagnostic revealed a flaw: some answers passed even though they omitted an `ORDER BY` or a `ROUND`, because the sample data happened to be sorted and the averages happened to be whole numbers. An audit showed that 14 of the 44 requirements in the prompts had no test enforcing them.

I replaced that manual audit with an automated one. For every problem, the check breaks the reference solution one requirement at a time:

- removes the final `ORDER BY` and reverses each sort key
- removes each `ROUND`
- applies problem-specific changes, such as dropping a date filter, changing `>=` to `>`, swapping `DENSE_RANK` for `RANK`, or grouping by name instead of ID

If no test catches a change, the check fails, and the problem doesn't ship until the data exercises that requirement. All 134 requirements across 22 problems now pass, and the check runs on GitHub with every change.

Two further checks protect the content. Each problem lists known wrong answers, including mistakes from my own attempts, that must fail a specific test. It also lists alternative correct answers that must pass, so the tests never accept only one way of writing a query.

## Technical details

- **SQLite in the browser.** The SQL engine runs client-side through sql.js (WebAssembly). There's no server, no data leaves the page, and progress is saved on the device.
- **MySQL syntax, as on LeetCode.** MySQL functions such as `QUARTER`, `DATEDIFF`, and `DATE_ADD(d, INTERVAL 1 DAY)` are rewritten into native SQLite expressions before a query runs. Registering them as JavaScript functions wasn't an option: sql.js returns every JavaScript number as a float, so `CONCAT('Q', QUARTER(d))` produced `'Q2.0'`.
- **No hand-typed answers.** Tests only add or remove rows. Expected results always come from running the reference solution on the same data, including any custom rows a user adds.
- **No framework or build step.** The site is plain HTML, CSS, and JavaScript, so a copy can be hosted anywhere, including for free on GitHub Pages.

## Use it yourself

The [repository](https://github.com/Mahabala-O/sql-lab) is a GitHub template. Copy it, enable GitHub Pages, and take the diagnostic. The guide in `docs/tailor-with-ai.md` provides prompts for turning your results into a ranked list of gaps, and then into a practice topic for the most important one. The built-in checks then review the draft, flagging any requirement without a test, any wrong answer that slips through, and any correct answer that's rejected.
